# プレイ画面レイアウト仕様

## 概要

本ドキュメントは、対戦画面（プレイマット）のレイアウト仕様を定義する。

レイアウトは、実際のカードゲームの操作感を重視し、PC・スマートフォンの両方で快適に操作できることを目的とする。

---

# 基本方針

* 相手エリア・自分エリアは **180°回転（上下左右対称）** の配置とする。
* 舞台を画面中央の主役として配置する。
* 手札は画面手前（操作しやすい位置）に配置する。
* カードの向き・重ね方は実際のプレイに近づける。

# カードの向き

## PositionによるStage表示方向

Stage Cardのpositionは、ownerによらず次の表示方向とする。

| Position | 表示方向 |
| --- | --- |
| `STAND` / `data-position="stand"` | 元のCard表示方向（0deg） |
| `REST` / `data-position="rest"` | 元のCard表示方向から左へ90°（-90deg） |
| `REVERSE` / `data-position="reverse"` | 既存の上下反転表示（180deg） |

RESTの左右方向はゲームロジック上の意味ではなく、weiss-onlineにおける表示規約である。self / opponentのどちらも同じposition semanticsを使用し、ownerによってRESTの意味を反転しない。また、Card画像が縦長か横長か、またはcardTypeが何かによってREST方向を変更しない。positionの盤面表示は右上Card詳細画像へ適用せず、詳細画像は元の縦横比と方向を維持する。

## F-3Dの画像方向対応範囲

F-3Dで元画像のアスペクト比を維持する対象は右上カード詳細だけとする。縦長・横長とも詳細領域内へ`contain`し、画像なし・ロード失敗は共通placeholderとする。手札、Stage、Clock、Level、Climax置場、Waiting Roomその他の盤面カードについて、元画像・zone・所有者に基づく新しい方向・回転ルールはF-3Dでは設計・実装していない。StageのSTAND / REST / REVERSEはCard画像自体の向きとは独立したposition表示として、上記の共通規約に従う。

| エリア     | 向き |
| ------- | -- |
| 手札      | 縦  |
| 舞台      | 縦  |
| 山札      | 縦  |
| 控え室     | 縦  |
| レベル     | 縦  |
| クロック    | 縦  |
| ストック    | 横  |
| 思い出     | 横  |
| クライマックス | 縦  |

## Resolution / Deck Search（F-4B）

Resolutionはself/opponentで対称なDeck / Memory近傍へ一時表示し、通常Zoneの黒い矩形枠を用いない。Deck Searchは盤面上のmodalに全山札を左から右へ折返し表示し、選択可否と選択中を視覚的に区別する。

## UI Layer / Modal Detail（Phase F-4B UI/UX Follow-up 2）

UI layerは背面から `Normal Board < Phase Notification < Modal Backdrop < Modal Content` とする。CSS custom propertyの`--z-phase`、`--z-modal-backdrop`、`--z-modal`でこの順序を明示し、Modal表示中に「メインフェイズ」等の通知を前面へ出さない。

十分な横幅ではModal内をカード一覧（可変幅）とCard Detail（240〜300px）の2列にし、一覧とDetailを個別にscroll可能とする。Modal panelはviewport内の最大高に制限し、選択数と確定ボタンを一覧scrollの外に置く。760px以下では1列の縦配置へ切り替え、Modal panel全体を縦scrollするため、Detailが画面外へ固定されない。
