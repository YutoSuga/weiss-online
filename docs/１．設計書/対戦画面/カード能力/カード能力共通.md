# カード能力共通設計

## 目的と責務

本書は、対戦画面で扱うカード能力の分類と、設計書を追加・更新するときの責務境界を定める入口である。`CardAbility` のデータ構造はシステム共通の[CardMaster / CardAbility設計](../../システム共通/カードデータモデル.md)、能力の中断・再開は[Process設計](../../システム共通/プロセス.md)、Rule Checkとの順序は[Rule Check設計](../../システム共通/ルールチェック.md)を正本とする。

カード能力は実装順ではなく、ゲーム上のAbility typeとkeywordで分類する。

```text
カード能力
├── カード能力共通（本書）
├── 起動効果
│   ├── ACT能力共通
│   └── キーワード能力
│       └── 集中
└── 自動効果
    ├── AUTO能力共通
    └── キーワード能力（必要になった時に追加）
        ├── アンコール
        ├── 加速
        └── チェンジ
```

## 共通設計とキーワード能力の境界

- **カード能力共通**: Ability type、CardAbility schema、システム共通設計との責務境界を案内する。
- **ACT能力共通**: ACTの使用可能判定、Cost / Effect、`ACT_ABILITY` Process、Check Point、interrupt / resumeを扱う。
- **AUTO能力共通**: Game Event、Trigger Detection、Pending AUTO、Check Timing、Turn Player / Non-Turn Player順、Cost Selection、`WAITING_INPUT`、`AUTO_ABILITY` Process、PRINTED / RULE / GRANTED sourceを扱う。
- **キーワード能力**: 共通基盤を利用するゲームルール上の意味、固有のTrigger / Cost / Effect / Processを扱う。設計内容が生じた時点で、対応するAbility typeの`キーワード能力/`へ追加する。

ACTとAUTOの共通基盤をキーワード固有仕様へ混在させず、キーワード側から共通設計を参照する。AUTOは特定フェイズの機能ではないため、フェイズ配下には置かない。フェイズ開始・終了を契機とするAUTOでは、フェイズ側がGame Eventを発行し、AUTO側がTrigger Detectionする。

## 個別カードの扱い

個別カードごとの設計書は作成しない。個別カードは汎用Trigger / Condition / Cost / Effectの組み合わせとしてCardMasterへ定義し、必要な場合だけ共通設計書の実装例、CardMaster定義例、またはテストケースとして参照する。カード固有の分岐を共通基盤へ追加しない。

## 現在の正本

- [ACT能力共通設計](起動効果/ACT能力共通.md)
- [集中（BRAINSTORM）詳細設計](起動効果/キーワード能力/集中.md)
- [AUTO能力共通設計](自動効果/AUTO能力共通.md)

アンコール、加速、チェンジの専用設計書は未作成である。実装対象になり、共通設計だけでは表せないゲームルール上の仕様が確定した時点で、自動効果の`キーワード能力/`へ追加する。

## F-5D以降の更新先

- **F-5D-1 標準3コストアンコール**: AUTO能力共通へRule Ability / Game Event / Pending / Cost / Process境界を反映し、固有ルールが確定した場合は自動効果のキーワード能力として「アンコール」を追加する。
- **F-5D-2 手札から舞台に置かれた時のPRINTED AUTO**: AUTO能力共通へ`CARD_MOVED` TriggerとEffect解決の共通仕様を反映する。対象カード専用設計書は作らない。
- **F-5D-3 クライマックスフェイズ開始AUTO / 加速**: フェイズ設計へ`PHASE_STARTED` Eventの発行境界、AUTO能力共通へTrigger Detection、固有仕様が確定した場合は自動効果のキーワード能力として「加速」を反映する。対象カード専用設計書は作らない。
