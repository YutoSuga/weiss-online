# アンコール詳細設計

## 標準3コストアンコール

全Characterがルール上持つ標準アンコールは、各CardMasterへ複製せず`source.kind = RULE`、Ability ID `STANDARD_ENCORE_3`のAUTOとして共通定義する。

| 項目 | 仕様 |
| --- | --- |
| Trigger | 自身のCharacterが`CARD_MOVED: STAGE → WAITING_ROOM`となった時 |
| Cost | `PAY_STOCK 3`。対象選択UIなし |
| Effect | 対象instanceを移動直前のStage row/indexへ戻す |
| Position | 元の状態によらず必ず`REST` |
| 使用不能 | 対象が現在Waiting Roomにない、3 Stockを払えない、または将来の共通禁止条件 |

元slotは`CARD_MOVED.payload.from`からPendingの`triggerContext.originalStagePosition`へimmutable snapshotし、Cardへ恒久保存しない。誘発と使用可能性は分離し、使用不能Pendingも理由とともに表示する。

## Stage配置と圧殺

Effectはアンコール専用の配置・圧殺処理を持たず、手札からのCharacter Playでも使う指定slotへの共通Stage配置処理を呼ぶ。

1. slotが空なら対象を配置する。
2. 別Card Bがいれば、Bを先にStageからWaiting Roomへ通常移動する。
3. 対象AをWaiting Roomから同じslotへ通常移動し、RESTにする。

両移動は`CARD_MOVED`を発行する。したがってBがCharacterならBのRULE Encoreが誘発し、AのWaiting Room → Stageも将来のPRINTED AUTOで検出可能である。同一instanceの再誘発を抑止しないため、Stock等が許せばA→B→Aの連鎖が成立する。

## 解決境界

```text
A ENCORE_RETURN中
  B Stage → Waiting Room
  → CARD_MOVED → Trigger Detection → B Pending追加（即時）
  A Waiting Room → Stage / REST
  → CARD_MOVED → Trigger Detection → Pending追加（即時）
A AUTO_ABILITY完了
  → Rule Check
  → Check Timing
  → B等のPending選択
```

Event発行からPending追加までは同期的だが、Check Timingは現在のAUTO Process完了後である。新Pendingを現在のEffectへ割り込ませない。

## 対象外

手札アンコール、カード固有Cost、「アンコールできない」具体効果、汎用Condition / Effect DSLは本Phaseでは実装しない。
