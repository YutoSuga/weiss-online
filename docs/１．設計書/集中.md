# 集中（BRAINSTORM）詳細設計

## 集中の位置付け

`BRAINSTORM`（表示名「集中」）はAbility Typeではなく、`ACT`へ付与するAbility keywordである。F-4B時点で初めて実行対応するkeywordであり、他keywordは先行定義しない。AUTO能力は登録・実行しない。

## 基本構造

```text
BRAINSTORM_REVEAL → effectResults[Effect.id] → 後続Effect / EFFECT_GROUP
```

`effectIndex`はACT Processのトップレベル進行位置、`Effect.id`はCardAbility内（Group階層を含む）で一意な結果識別子であり、置換関係ではない。`effectResults`はACT contextだけに存在し、終了時に破棄する。Cardは保存せず`instanceId`を保存する。`EFFECT_RESULT`参照は`effectId`と`field`を明記し、欠落・型不一致を例外にする。

## Resolution

`RESOLUTION`はPUBLICな正式Zoneで、`Player.resolution`としてself/opponent別々に保持する一時領域である。集中で追跡したinstanceだけを`Deck → Resolution → Waiting Room`へ移し、先に存在した無関係なResolution Cardを移動しない。UIは空なら非表示、存在時だけDeck / Memory付近へ黒いZone枠なしで公開表示する。

## 人気アイドル 西森 柚咲

```text
Cost: PAY_STOCK 1 → REST_SELF
Effect: BRAINSTORM_REVEAL 4
        → effectResults.brainstormReveal.climaxCount
        → CX >= 1 のEFFECT_GROUP
        → SEARCH_DECK → ADD_TO_HAND → SHUFFLE_DECK
```

検索filterはCHARACTERかつtraitが`Anniversary`または`能力者`のいずれか。`minSelect=0`、`maxSelect`はclimaxCount参照である。

## Refresh interrupt / resume

```text
Deck残り2 → 2枚 Resolution → Deck=0
→ 既存REFRESH → 既存REFRESH_PENALTY
→ ACT / BRAINSTORM_REVEAL resume
→ 残り2枚 Resolution → 計4枚のCX count → Waiting Room
```

ACT contextのbrainstorm作業状態にeffectId、targetCount、移動済みinstanceIdを保持する。ResolutionのカードはRefresh対象のWaiting Roomへ混入しない。

## CX数による分岐

- CX=0: Group全体をskipし、Deck Search、手札追加、Shuffleを行わない。
- CX=1: Deck全体から0～1枚を一括選択し、追加後にShuffle 1回。
- CX=N: Deck全体から0～N枚を一括選択し、まとめて追加後にShuffle 1回。

F-4BはShuffleを誘発・参照するAbilityを扱わない。この一括検索 + 1回Shuffleの簡略化は、Shuffleに反応するAbility導入時に再評価する。

## Process Stack

```text
MAIN_PHASE / WAITING_INPUT
  └ ACT_ABILITY / RESOLVE_EFFECT
       └ SEARCH_DECK / PREPARE → WAIT_FOR_SELECTION → COMPLETE
```

SEARCH_DECK完了でpopし、ACTへresumeして結果を`effectResults.searchDeck.selectedCardInstanceIds`へ保存する。ACT完了後は親MAINへ戻る。
