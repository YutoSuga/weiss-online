# テストチェックシート運用

## 目的

このディレクトリは、関数単位の単体テスト一覧ではなく、**ユーザーから確認できる操作・画面表示・ゲーム状態**を単位とした結合レベルの確認観点を管理する正本である。自動テストを置き換えるものではなく、画面を通した一連の動作を補完する。

## 対象

対象はゲーム開始、フェイズ進行、カード選択・詳細表示・移動、Cost、ACT、AUTO、モーダル、Effect解決後の通常操作への復帰などとする。private method単位、内部関数単位、DEVパネル等の開発支援機能は対象外とする。

## 記録値

| 列 | 意味 | 原則使用する値 |
| --- | --- | --- |
| 自動確認 | 自動テストによる確認状況 | 済 / 未 / 対象外 |
| 実機確認 | 実際のブラウザ画面をユーザーが操作した結果 | OK / NG / 割愛 / 対象外 |
| 備考 | 確認条件、NG内容、特記事項 | 簡潔な自由記述 |

ブラウザ実機確認を実施できない環境では、実際に確認していない項目をOKにしない。

## 更新ルール

機能追加・仕様変更時は次の順で更新する。

1. 変更によって新しい画面上の確認観点が増えた場合、まず[チェックシートひな形](チェックシート_ひな形.md)へ観点を追加する。
2. 今回の確認用として、ひな形を基に実施結果用チェックシートを作成する。
3. 自動テストで確認済みのものは「自動確認」を更新する。
4. 実際にブラウザで確認したものだけ「実機確認」をOK / NGにする。
5. 今回確認しなかったものは「割愛」としてよい。
6. 毎回全項目を実機確認する必要はない。
7. 今回の変更に関連する観点を優先して確認する。
8. NGが見つかった場合は備考へ簡潔に内容を記録する。

この運用を全件毎回必須の巨大な手動回帰テストにはしない。実施結果は`実施結果/`へ日付と対象が分かる名前で保存する。

## ブラウザ確認の補助操作

旧`test.md`の備忘を現行実装で確認して移管した。開発用画面では`main.dev.js`が次の変数を`window`へ公開しているため、Chromeの開発者ツールでConsoleを開いて利用できる。

```js
// 現在状態で再描画
renderer.render(gameState);

// テスト用card1を手札へ追加して再描画（状態整合性を保証しない直接操作）
gameState.players.self.hand.push(card1);
renderer.render(gameState);

// 次フェイズへ進める（入力待ちProcess中などは例外になる）
gameEngine.nextPhase();
```

コマンド自体は現在も公開変数/APIとして有効である。ただし手札への直接`push`はCardのzone/indexや元collectionを更新せず、Game Eventも発行しない古い簡易操作である。通常の結合確認ではDEVパネルまたはGameEngineの正規操作を優先し、このコマンドは表示調査だけに限定する。
