# 依頼：DEV Panel UI改善

現在、weiss-online の開発中に使用しているDEVパネルについて、
ボタンや確認項目が増えてきて使いづらくなってきたため、
UIを改善してください。

今回はDEV PanelのUI改善のみを行い、
GameStateやゲームロジックには影響を与えないでください。

==================================================
■ 今回の目的
==================================================

DEV Panelを、

・必要な時だけ展開できる
・不要な時は小さく折りたためる
・項目が増えても画面からはみ出さない
・State / Process / Rule / Actionsが見分けやすい

状態にします。

ゲームルールやProcess処理自体は変更しません。


==================================================
■ 1. 事前確認
==================================================

実装前に、現在のDEV Panelに関係する以下を確認してください。

・DEV PanelのHTML
・DEV PanelのCSS
・DEV PanelのController / Event Listener
・DEV情報更新処理
・Process Stack表示
・Rule Check表示
・DEV Action buttons
・既存の右サイドバーとの重なり
・レスポンシブ / PC画面表示

現在のDOM構造・クラス名・命名規則をなるべく活かしてください。

大規模なHTML再構成は避け、
必要最小限の変更で実装してください。


==================================================
■ 2. DEV Panel全体の折りたたみ
==================================================

DEV Panelのヘッダーに、
展開 / 折りたたみボタンを追加してください。

展開時：

DEV                  [−]

のような表示。

折りたたみ時：

DEV                  [+]

のような表示。


ボタンの記号は、

展開中
→ −

折りたたみ中
→ +

としてください。


==================================================
■ 3. 折りたたみ時の表示
==================================================

折りたたみ時は、
DEV Panelの中身をすべて非表示にしてください。

非表示対象：

・State情報
・Process Stack
・Rule Check
・DEV Action buttons
・その他DEV内部情報


ただし、
DEVヘッダー自体は残してください。


イメージ：

┌────────────────┐
│ DEV          [+] │
└────────────────┘


折りたたみ時は、
できるだけ小さくコンパクトにしてください。


==================================================
■ 4. 展開時の表示
==================================================

展開時は、
現在のDEV Panel内容を表示してください。

ただし、
画面高を超えてパネル全体が伸び続けないようにしてください。


以下のような考え方で、
DEV Panelの最大高さをViewport内に制限してください。

例：

max-height: calc(100vh - 任意の余白);

overflow-y: auto;


具体値は現在のレイアウトを確認して調整してください。


重要：

DEV Panel全体が画面下へはみ出すのではなく、

パネルの外枠
→ 画面内

内容が多い場合
→ DEV Panel内部だけスクロール

となるようにしてください。


==================================================
■ 5. State / Process・Rule / Actionsの整理
==================================================

現在のDEV Panel内部を、
視覚的に以下の3カテゴリへ整理してください。


1.
State

例：

started
turn
turnNo
phase


2.
Process / Rule

例：

Process Stack
Rule Check
pending
check


3.
Actions

例：

次フェイズ
自分1枚ドロー
相手1枚ドロー
再描画
Stack確認
リフレッシュ
手札を1枚クロックに置く
山札を1枚クロックに置く
レベルアップ
共通チェック確認
Rule Check解決
その他既存DEV Action


既存の情報やボタンを削除しないでください。


==================================================
■ 6. カテゴリ表示
==================================================

各カテゴリは、
見出し等で明確に区別してください。

例：

State
----------------

Process / Rule
----------------

Actions
----------------


現在のDEV Panelデザインに合うように、
視覚的に整理してください。


今回の段階では、
カテゴリごとの個別折りたたみまでは不要です。

DEV Panel全体の折りたたみだけ実装してください。


==================================================
■ 7. DEV Action buttons
==================================================

既存のDEV Action buttonsは、
現在の機能をすべて維持してください。

今回のUI変更によって、

・イベントが発火しなくなる
・button idが変わる
・Controllerが参照できなくなる

等が起きないよう注意してください。


ボタンの並びについては、
現在の2列レイアウト等を活かしつつ、
見やすい範囲で調整して構いません。


ただし、
各DEV Actionのゲーム処理は変更しないでください。


==================================================
■ 8. 折りたたみ状態の管理
==================================================

DEV Panelの展開 / 折りたたみ状態は、

GameStateに保存しないでください。


これはゲーム状態ではなく、
DEV UIのみの状態です。


以下のいずれかで管理してください。

・DOM/UIローカル状態
・DEV Panel Controller内の状態


今回はlocalStorageも不要です。

ページ再読み込み時に
初期状態へ戻って問題ありません。


初期状態は現在と同様、

展開状態

としてください。


==================================================
■ 9. GameStateへの影響禁止
==================================================

DEV Panelの折りたたみ操作によって、

・GameState
・GameEngine
・ProcessManager
・Phase
・turn
・processStack
・ruleState

等を変更しないでください。


DEV Panel collapse / expandは、
完全にUIだけの操作としてください。


==================================================
■ 10. DEV情報の更新
==================================================

折りたたみ中であっても、
既存のDEV情報更新処理を壊さないでください。


再度展開した際に、

古い情報ではなく、
現在のGameState / Process状態

が表示されるようにしてください。


現在のRenderer / DEV更新処理が
常時DOM内容を更新している場合は、
その仕組みをそのまま利用してください。


折りたたみのためだけに、
新しいGameState同期機構を作らないでください。


==================================================
■ 11. 右側UIとの重なり
==================================================

現在DEV Panelが、
右サイドバーのカード説明 / 自分情報等へ
大きく重なっています。


展開時：

現在のfixed / absolute等の配置方針は、
必要以上に変更しなくて構いません。


ただし、

・画面高さからはみ出さない
・内部スクロールできる
・折りたためばカード説明等を確認しやすい

状態にしてください。


折りたたみ時は、
右上に小さなDEVヘッダーだけが残るイメージです。


==================================================
■ 12. Scroll
==================================================

展開時に内部スクロールが発生した場合、

DEV Panelのヘッダーが
可能であれば常に見えるようにしてください。


例えば、

DEVヘッダー
→ 固定 / sticky

DEV content
→ scroll

のような構造を検討して構いません。


ただし、
現在のHTML構造に対して変更が大きくなる場合は、
無理にsticky化しなくて構いません。

最優先は、

「折りたたみボタンへいつでもアクセスできる」

ことです。


==================================================
■ 13. UIデザイン
==================================================

現在のDEV Panelの、

・濃い背景
・オレンジ系の枠 / ボタン
・monospace系表示

等のデザインは維持してください。


全体のデザインを作り直すのではなく、
現在の見た目を活かして整理してください。


折りたたみボタンも、
既存のDEV UIに馴染むデザインにしてください。


==================================================
■ 14. Accessibility / Interaction
==================================================

折りたたみボタンは、
button要素等の適切な操作要素を使用してください。


可能であれば、

aria-expanded

等を設定して、
展開 / 折りたたみ状態が分かるようにしてください。


マウスだけでなく、
通常のクリック / タップで操作できるようにしてください。


Drag & Dropは不要です。


==================================================
