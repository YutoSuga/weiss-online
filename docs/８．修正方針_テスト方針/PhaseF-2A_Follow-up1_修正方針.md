■ 1. カード画像表示について
==================================================

右側のカード説明エリアについて、
将来的には選択中カードの画像も表示したいです。

ただし今回はカード画像表示を実装しないでください。

理由：

現在はまだCardMaster未導入で、
Cardに画像パス / imageUrl等の正式なマスターデータ構造がありません。

今ここで暫定的な画像プロパティをCardへ追加すると、
F-3 CardMaster導入時に二重管理や移行作業が発生するためです。


今回やること：

・現在のカード説明UIはそのまま維持
・カード画像表示機能は追加しない
・F-3 CardMaster導入時の将来要件として設計書へ必要最小限の追記を検討

将来的には概念的に、

CardMaster
  image / imagePath / imageUrl

等からRendererが右カード説明内へ画像表示する想定です。

ただしプロパティ名や保存方式は今回確定しなくて構いません。


==================================================
■ 2. 相手CLOCK Phaseから先へ進めない問題
==================================================

現在、相手ターンのCLOCK PhaseでDEV Panelの「次フェイズ」を押しても、
先へ進めなくなっています。

画面上では以下の状態になっています。

Process Stack:
type   clock_phase
player opponent
step   wait_for_selection
status waiting_input

つまりCLOCK_PHASEが、
「相手がクロックに置く手札を選択する入力待ち」
になっていると考えています。


--------------------------------------------------
■ 2-1. まず原因調査
--------------------------------------------------

修正前に以下を確認してください。

・DEV Panel「次フェイズ」が現在どのメソッドを呼んでいるか
・GameEngine.nextPhase()等の現在のPhase遷移条件
・CLOCK_PHASEのWAIT_FOR_SELECTION処理
・CLOCK Phaseで「クロックに置かない」をどう処理しているか
・自分側CLOCK UIで0枚選択 / スキップする既存APIがあるか
・F-1 / F-2A変更前にDEV「次フェイズ」で進めていた理由
・現在Process Stackが残ったままphaseだけ変更されないよう、どのガードが働いているか

原因を確認した上で修正してください。


--------------------------------------------------
■ 2-2. 修正方針
--------------------------------------------------

通常ゲームルールを壊すため、

DEV「次フェイズ」を
「Processを無視して強制的にphaseだけ変更するボタン」
にはしないでください。

以下のような壊れた状態は作らないでください。

phase = MAIN

なのに、

processStack:
CLOCK_PHASE / WAIT_FOR_SELECTION

が残る状態。


今回の推奨方針は、

相手CLOCK Phase用のDEV操作を追加することです。


例：

「相手クロックをスキップ」

または分かりやすい同等名称。


この操作では、

CLOCK_PHASE / WAIT_FOR_SELECTION
↓
クロックに置かない選択を確定
↓
CLOCK_PHASEを既存の正常なルートで完了
↓
MAIN_PHASEへ進む

という流れにしてください。


重要：

既存CLOCK Phaseに
「0枚選択」
「スキップ」
「クロックしない」
に相当するGameEngine APIが存在するなら、
必ずそれを優先して利用してください。

DEVから直接、

・processStackをpopする
・phaseを書き換える
・stepを書き換える
・statusを書き換える

といった強制操作は避けてください。


--------------------------------------------------
■ 2-3. DEV「次フェイズ」について
--------------------------------------------------

既存の「次フェイズ」ボタン自体は、
現在の用途を維持してください。

今回の問題解決のために、
通常ゲームのWAITING_INPUTを無視する強制遷移機能へ変更しないでください。

必要であれば、

・「次フェイズ」
・「相手クロックをスキップ」

を別DEV Actionとして共存させてください。

■ 3. DEV「山札TOP → Stock TOP」追加
==================================================

DEV PanelのActionsへ、

「自分山札TOP→ストック」

相当のボタンを追加してください。

表示名は既存DEVボタンの文字量・レイアウトに合わせ、
自然な日本語へ調整して構いません。


--------------------------------------------------
■ 3-1. 動作
--------------------------------------------------

自分PlayerのDeck一番上のカードを1枚取り出して、
自分Stockの一番上へ置いてください。

概念：

self deck TOP
↓
self stock TOP


Stockは現在の設計どおり、
配列末尾がTOPであれば、

stock.push(card)

となる想定です。

ただし既存Deck / Stockの内部順序を実装前に確認し、
現在のコード規約に従ってください。


--------------------------------------------------
■ 3-2. 移動後のCard状態
--------------------------------------------------

概念的には以下です。

zone     → STOCK
row      → null
index    → Stock TOP
position → STAND
face     → null

ただしindexについては、
現在のStock表現・Renderer・Card.moveTo()等を確認し、
既存方式に従ってください。


--------------------------------------------------
■ 3-3. Rule Checkは自動実行しない
--------------------------------------------------

このDEV Actionは、
テスト状態を意図的に作るための低レベルDEV操作です。

そのため、

・Rule Check
・REFRESH
・REFRESH_PENALTY
・Process開始

を自動実行しないでください。


例：

deckが1枚の状態で実行

deck:
1 → 0

stock:
+1

となっても、
その場ではREFRESHを開始しないでください。


その後、

・共通チェック確認
・Rule Check解決

等の既存DEV操作から、
別途ルール処理を試せる状態にしてください。


--------------------------------------------------
■ 3-4. 山札0枚時
--------------------------------------------------

山札が0枚の場合は、
何も移動しない安全な処理にしてください。

例：

・no-op
・DEV log出力
・console.warn

等、既存DEV実装の流儀に合わせてください。

例外で画面全体を停止させないでください。
